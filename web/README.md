# Clip Studio 작업 기록 연결본

기존 디자인의 작업 사본입니다. 원본 웹 폴더, Python 프로그램, SQLite DB는 수정하지 않았습니다.

## 단계와 현재 상태

1. 디자인 작업 사본 준비: 완료.
2. 샘플 데이터 대신 기존 Supabase의 work_time 조회 코드 연결: 구현 완료.
3. 주간 이동, 선택 시간 상세, 최근 365일 합산, 자동 갱신: 구현 완료.
4. 기존 스타일 유지, 시간축 간격 수정, 초 단위 표시, 시간당 60분 색상 보정: 완료.
5. 검증: 데이터 로직 테스트 3개 통과. 패키지 설치와 실제 Supabase 요청은 실행 환경의 네트워크 제한(EACCES/소켓 접근 거부)으로 차단됨. 전체 타입 검사·빌드·브라우저 실행·실제 DB 대조는 미완료.
6. 배포: 사이트 등록만 되었으며 버전 저장·게시하지 않음. 빌드 검증 후 진행해야 함.

## 실행

Node.js 24와 pnpm을 사용할 수 있는 네트워크 환경에서 이 폴더를 열고 실행합니다.

```powershell
pnpm install --frozen-lockfile
pnpm exec tsc --noEmit
node --test tests/data.test.mjs
pnpm dev
```

터미널에 표시된 로컬 주소를 엽니다. 배포용 정적 결과물은 `pnpm build` 성공 후 `out` 폴더에 생성됩니다.

기존 graph.html의 Supabase 주소와 publishable key가 기본값입니다. 변경하려면 `.env.example`을 `.env.local`로 복사해 수정하고 다시 실행/빌드합니다. 브라우저 코드에는 secret/service-role key를 넣지 않습니다.

## 데이터 흐름

기존 Python main.py → 로컬 SQLite → 기존 sync.py → Supabase work_time → 이 웹사이트.

Python 프로그램은 기존 WorkTracker 폴더에서 기존 환경 설정으로 실행합니다. 웹은 SQLite 파일을 직접 읽지 않습니다. Python의 로컬 서버는 이 웹 조회에 필요하지 않습니다.

DB의 date/hour/seconds를 브라우저에서 날짜·시간별로 묶고, 초를 분으로 변환해 기존 화면 컴포넌트에 제공합니다. 화면 표시에서는 초를 보존합니다. 일평균은 기존 디자인과 동일하게 주간 합계÷7입니다. 날짜는 기존 프로그램과 동일하게 로컬 시간 기준이므로 다른 시간대의 기기에서 볼 경우 경계가 달라질 수 있습니다.

첫 로딩과 오류를 별도로 표시하며 샘플 기록을 대신 표시하지 않습니다. 동일 조회 범위에서 갱신 실패 시 이전 기록을 유지합니다. 요청 완료 후 60초 간격으로 조회하므로 Python 업로드 주기와 합쳐 반영까지 약 2분 이상 걸릴 수 있습니다.

## 남은 실제 확인

- 위 설치·타입 검사·빌드가 성공하는지 확인.
- 웹의 주간 합계와 SQLite 날짜별 합계 비교.
- 기존 Python 프로그램으로 작업 후 Supabase 및 웹 반영 확인.
- 주 이동, 연간 날짜 클릭, 무기록 날짜, 네트워크 오류 후 재시도 확인.
- 밝은/어두운 화면과 모바일에서 원본 디자인 비교.
- Supabase의 기존 테이블 및 공개 조회 권한(RLS)이 의도한 설정인지 확인. 이 작업은 원격 테이블이나 접근 정책을 변경하지 않았음.

새로 등록한 Sites의 연결 정보는 `.openai/hosting.json`에 있습니다. 빌드가 성공한 후 같은 사이트를 재사용하여 게시합니다.
